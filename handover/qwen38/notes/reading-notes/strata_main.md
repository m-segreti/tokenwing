## 1. Decode path for one token (a "verify window" of T = 1..8 tokens; T = 1 is plain decode)

**Unit of work = one captured CUDA graph per window size T.** `Verifier::record_window` (`src/core/verify.cpp:1339`) records all 48 layers + the head
into one stream; `Verifier::capture` (`verify.cpp:2752-2790`, `cudaStreamBeginCapture` at 2763) instantiates it; `exec_[sel_long_][T]` is reused
(2754). Inputs (token ids, step/position tables) are copied from mapped pinned host memory inside the graph (`verify.cpp:1422-1432`).
There are two graph kinds: a **zero-doorbell graph** when every expert of the stage is in VRAM (`all_resident_`, `verify.cpp:1258-1323`, comment 369)
and a **doorbell graph** when some experts live in RAM (`verify.cpp:1395`: "0 = zero-doorbell all-resident, 1 = doorbell graph with CPU / PCIe experts").
`refresh_ar` / `ar_on()` switch between them per window (`verify.cpp:2733-2750`).

**Per layer** (`pre(l)` `verify.cpp:1476`, `post(l)` `verify.cpp:2341`; order `pre(0); for l: post(l); pre(l+1)` at 2527-2531):
1. *Hyper-connection (mHC) read, attention half* - `gr_read_group(0,...)` (`verify.cpp:1590, 1614`) -> `fused_gr_read_multi`
   (`include/strata/kernels/fused_gr.hpp:1-14`, `src/kernels/cuda/fused_gr.cu`). Two kernels: `fused_gr_down` folds the *previous half's write*
   (`R' = R + bo_prev * 2 sigmoid(inj_prev/hc)`), RMS-norms the 4 streams (`xn = R' * w_norm * rsqrt(mean(R'^2)+eps)`), then
   `lo = silu((w_down . xn)/hc)` (320 rows) and `inject = w_inject . xn`; `fused_gr_up` writes `R'` back and computes
   `mixed[d] = mean_c xn[c,d] * sigmoid(w_up[c*2560+d] . lo)`. FP32 activations, BF16 weights (or the file's Q8_0 with `STRATA_HC_Q8`, `fused_gr.hpp:46-62`).
   One launch pair serves all T tokens (weights read once, `fused_gr.hpp:73-84`).
2. *Mixer.* GDN layer (`verify.cpp:1655`): q8_1-quantise `mixed`, qkv projection, `gdn_conv_l2_multi` (conv + L2 norm; fused with the a/b gate GEMV in
   `gdn_conv_ab_multi`, 1700-1715), gate projection z, recurrence from the untouched state over the T tokens (state only advanced by `commit`,
   `include/strata/core/verify.hpp:1-22`). QSA layer (`verify.cpp:1794`): q projection, q/gate split + RMSNorm + RoPE (`native_qsa_rms_norm_rope`),
   indexer key/query projections (BF16), indexer tail append, block scores + top-k selection (`qsa_block_scores`/`qsa_block_topk`, 1911-1925),
   `qsa_decode_attn_batch` over the selected cells (2080-2154). Side-stream branches (`STRATA_SIDE_MIXER`) overlap the gates/indexer with the projections (1355-1360, 1700-1760).
   Output projection `mm(wo, bo_...)` (2170-2172).
3. *Hyper-connection read, FFN half* - `gr_read_group(1,...)` (2179) -> `mixed_` (+ q8_1 image for the CPU experts).
4. *Router* (`verify.cpp:2197-2212`): BF16 GEMV `ffn_gate_inp` (512 logits) + `native_router_top10_multi`. Contract: softmax over **all 512**, stable
   descending top-10, renormalise with a 2^-14 clamp, no selection bias (`include/strata/kernels/native_router.hpp:10-17`,
   `include/strata/kernels/router_top10.hpp:3-7`). The order of `ids_` is router rank (rank 0 = largest weight).
5. *Plan.* If the stage is all-resident, `resident_plan` (device kernel) builds the per-expert groups from the residency table `hits_.d_res`
   (2246-2250). Otherwise `doorbell_publish_res` copies `mixed`, ids and the residency row into mapped host memory and raises a doorbell (2262-2272).
6. *Shared expert* (2283-2316): `shared_expert_multi`: `h = silu(x Wg) * (x Wu)`, `h Wd`, scaled by `sigmoid(x w_gate_inp_shexp)` (one scalar per token),
   added **unweighted** after the routed sum (`include/strata/kernels/shared_expert.hpp:1-9`; `native_moe.hpp:11-18`). Runs on a forked stream beside the experts (2181-2194, 2318).
7. *Experts* (`post`, 2341-2476):
   - GPU-cached experts: `native_expert_grouped` over the plan's groups (2386 all-resident -> straight into `parts_`; 2405 partial -> `hit_out_`).
   - CPU: the host thread (`Verifier::run`, `verify.cpp:3229`) spins on a mapped `seq` word per layer (3441, "layer rang"), then calls the pool
     (`pool(user, h_x_, h_ids_, n, k, h_ymiss_, l)`, 3495) = `expert_pool_dispatch_multi` (`src/core/expert_source.cpp:4888`...): it decides, per distinct
     expert, VRAM hit (kind 0), PCIe share (kind 1), tail-skip (kind -2), CPU (kind -1) (4999-5090), publishes the GPU plan (`flagA`), starts the PCIe DMA
     (`flagB`), quantises the activation per token (5185-5200) and computes the CPU experts in the worker pool; the CPU rows go to `h_ymiss_` and flag `m_flag_` is raised (`*flag = want`, verify.cpp:3532).
   - PCIe share: the GPU computes some missed experts itself from pinned RAM blobs copied to a staging ring (`fetch_blobs`/`rebase_ptrs`, 2411-2421; `grouped(p_ptr2...)`).
   - Graph side: `wait_flag_ge_or(m_flagA_)`, copy plan, VRAM groups, `wait_flag_ge(m_flagB_)`, PCIe groups, `wait_flag_ge(m_flag_)`, then
     `copy_rows_from_mapped(_after)` copies only the CPU rows (2391-2442); spin-wait kernels on mapped host words, **no host driver sync per layer**
     (earlier study: same, `docs/others-code-study.md:107-113`).
8. *Combine* (2458-2476): `native_moe_combine_multi_hits_added` = parts (CPU rows) + GPU hit rows (`moe_hit_add` folded in, `hits_in_combine`), weighted by the router
   weights `w_`, plus `shared_`, plus the block output `bo_` (first product rounded to F32, then FMA in expert order, `native_moe.hpp:11-18`).
   Then the layer's FFN write is *not* applied yet; it is folded into the next layer's read (step 1) except on the last layer (2507-2512).
9. *Head*: final `output_hc_*` mixer + head matvec for T columns + argmax per column (2519-2560); MTP/DFlash2 drafter runs between windows (below).

**Speculation.** Setup writes `--spec 4 --spec-min-p 0.5 --mtp` (`strata_control/setup_config.py:218-219`); with DFlash2 `--spec 6 --draft-conf 0.35`
(`strata_control/drafting.py:254-257`). The window's tokens are verified "bit for bit" per row for the *kernel* arithmetic
(`include/strata/core/verify.hpp:1-9`), but CPU experts round a lone token differently from a group (`docs/DETAILS.md:347-351`), so drafting can still change a greedy text.
PLE rows of every draft token are fetched ahead (section 3).

**Residual-stream numerics:** recurrent state fp32 (`verify.cpp:1349-1351` gdn_floats), K/V fp16 by engine default (`src/program/generate.cpp:671`) but setup writes `--kv int8` above 8K context (`strata_control/setup_config.py:221-222`).

## 2. Expert memory tiers today

### 2.1 VRAM expert cache
- **What it is:** `ExpertCache` (`include/strata/core/expert_cache.hpp:86-250`): slot storage + residency table `(layer, expert) -> slot | -1`; fills from the host copy, *computes nothing*.
- **Sizing (`--expert-cache auto`, default in setup, `setup_config.py:218`):** slots = (free VRAM - `--vram-reserve-mib` (default 700, `generate.cpp:800`) - prompt-path buffers - draft head - pipeline verifier - 256 MiB
  "late allocations") / largest blob (`include/strata/core/auto_cache.hpp:14-41`, `generate.cpp:8037-8100`). After allocation it re-reads free VRAM and shrinks if short (8410-8445). Small-card rules: lower the reserve to 300 MiB, a smaller prompt chunk, or move the output head to pinned host memory (`generate.cpp:8100-8200`).
  Slot size = max blob over layers; native packs keep per-layer sizes via `open_sized` (8404-8406). 12 GB card at 4K context ~ 1,280 slots = 3.7 GiB of 24,576 (`docs/UNSLOTH_Q4.md:~70`); RTX 5070 Q2_0 ~ 4,500 slots (`docs/DETAILS.md:85-88`, earlier study).
  A 12 GB card also loses ~0.7-1 GiB to the draft layer (`DETAILS.md:339`; DFlash2 890 MiB / MTP 1,082 MiB, `strata_control/drafting.py:~70`).
- **Fill / policy:** *static profile first*: `--expert-profile data/expert-profile.bin` = ranked (layer, expert) pairs (`expert_cache.hpp:40-56`); the first `slots` pairs of the **global** ranking are copied (no per-layer quota unless `--expert-cache-per-layer`) (`generate.cpp:8486-8530`); then slot 0 is read back and byte-compared (`generate.cpp:~8553`, `ExpertCache::verify_slot` `expert_cache.hpp:214-217`). `ExpertCache::admit` itself never evicts (`expert_cache.hpp:157-160`).
- **Adaptation (default ON):** `usage[layer][expert] += 1` for every routed entry (`expert_source.cpp:4933`). Every `--adapt-every 4` verify windows (`generate.cpp:888`; first N windows faster for spec runs: 4390-4405) the engine takes per layer the non-resident experts with decayed count >= 2.0 (`generate.cpp:13203`) and swaps them for the least-used resident ones if count gain >= `adapt-min-gain` 1.5 (13212, option 896); at most `--adapt-swaps 96` swaps per round (924, 13217), most-improving first; counts x `--adapt-decay 0.7` after each round (893, 13357). Copies come from the RAM copy; an evicted expert's slot is reused immediately; overlap variants are opt-in (`STRATA_ADAPT_OVERLAP`, `--adapt-async`, `DETAILS.md:1078-1080`). The result is **not reproducible run to run** (`DETAILS.md:573`, `tools/tune_knobs.py` answer class "nonrepeatable"). Optional learned-profile save: `--expert-profile-save` (`DETAILS.md:391-396`).
- **PCIe-fetched admission (new, opt-in):** `STRATA_ADAPT_FETCH=1|2` copies a fetched expert straight into a victim slot (`expert_source.cpp:5008-5133`, `DETAILS.md:1080`; +10.2 % decode IQ3_S RTX PRO 5000, 16 % cached, `--pcie-frac 0.25`).
- **Counts (published):** 24,576 expert pairs total; "every extra GB holds about 700 more experts" (`DETAILS.md:85`).

### 2.2 RAM tier
- **Normal mode: all experts in one pinned arena** (34 GB Q2_0, 36 IQ2_XS, 43 IQ3_XXS, 50 IQ3_S + ~6 GB; `DETAILS.md:96-103`, `MODELS.md:36-43,119-135`). Allocation `cudaHostAlloc(Mapped|Portable)` or paced `cudaHostRegister` (`expert_source.cpp:3850, 3958, 4001`); huge pages tried (6046-6062). Fits when RAM >= experts + ~10 GB (`MODELS.md:131`). CPU computes misses **in place** from the arena, concurrent with the GPU (`docs/HOW_IT_WORKS.md:27-30`).
- **When RAM is smaller than the experts** (the case for 30 GB RAM + Q2_0; chosen by setup or by the engine, `DETAILS.md:242-283`):
  - `--mmap-experts`: maps `experts.bin` or the GGUF itself; the OS page cache is the RAM cache (kernel LRU, nothing of ours).
  - `--resident-experts`: copies exactly the experts the GPU does not hold into RAM if they fit.
  - `--resident-budget-gib N`: RAM holds the **profile-ranked hottest** non-GPU experts up to N GiB, the rest read from files (`expert_source.cpp:3608-3628`, static ranking at start). Setup: N = RAM - 24 GB (`docs/UNSLOTH_Q4.md:~36-40`).
  - **Automatic fallback (new since the old study):** if the arena does not fit after waiting up to 20 s, `generate.cpp:7781-7835` switches to the budget form by itself (hottest experts in available RAM minus headroom 4 GiB, 8 GiB on Windows; rest read from the file; `include/strata/core/resident_ram_copy.hpp:11-24`). On Linux, if free memory + droppable file cache + a reserved hugetlb pool can hold the arena it loads anyway (`expert_source.cpp` #5327 diff, `DETAILS.md:742-748`). Their own measurement: plain file source 9-10 tok/s vs RAM copy of hottest experts 27-28 tok/s on a 63 GB PC (`generate.cpp:7800-7804`).
  - Optional RAM-tier adaptation `STRATA_RAM_ADAPT=n`: a layer swaps up to 4 pairs per window, experts with decayed count >= 2 replace RAM places with count < 0.5; the incoming expert is copied from its stage buffer if the previous window read it (`DETAILS.md:257-265`; +16.5 % on one RTX 3060 / 32 GB / IQ2_XS, `DETAILS.md:1486`).
- **How file reads happen** (details in section 3): zero-copy compute from the page cache when all pages are cached; whole-blob `pread` prefetch on 8 I/O threads for the layer's uncached experts plus the *router-predicted* experts of the next 2 layers; or unbuffered O_DIRECT reads. Prompt: planner shrinks the chunk when the page cache is smaller than the file set (`DETAILS.md:305-310`).

### 2.3 "Lending idle K/V memory to experts" = `--kv-grow` (opt-in) and the prompt loan (default)
- `--kv-grow` / `STRATA_KV_GROW=1`: the expert cache lives in a CUDA virtual-memory range; the K/V takes 2 MiB chunks only for cells that are reached (initial 16,384 cells, `STRATA_KV_GROW_INIT`), the cache gives slots up as the context grows and takes them back after (`include/strata/core/vmm.hpp:1-6`, `generate.cpp:6772-6793`, `kvg_ensure` 10166). Needs: one GPU, a profile, whole K/V in VRAM, every expert in RAM, no `--batch`. Pays on cards <= ~24 GB with >= 128K context (`DETAILS.md:237`). Measured: Radeon AI PRO R9700, Q2_0, 196,608 ctx, 5 pairs, slots 6,213 -> 7,968, decode 96.3 -> 98.5 tok/s (x1.023); at 262,144 the default did not start, kv-grow started with 7,877 slots (94.4 tok/s) (`DETAILS.md:1443`). In the tuner it is a "thorough only" arm (`strata_control/tune_knobs.py:123-125`).
- **KV streaming** (default in setup from 64K context when RAM allows): the whole K/V in pinned RAM (13.7 KB RAM per token at int8), only 32,768 cells per QSA layer in VRAM (`--kv-resident 32768`); +6 % at 128K, +23 % at 262K with Q2_0 on RTX 5070 (`DETAILS.md:236`, `setup_config.py:~283-300`, `DETAILS.md:1433`). `STRATA_KV_PREFETCH=1` overlaps the K/V uploads in prompts (-5.3 % at 32K, `docs/KV_PREFETCH.md:1-35`, opt-in, one tester's 2x RTX 3080).
- **Prompt loan:** the prompt path borrows expert-cache slots for its buffers, keeping 128 slots (`generate.cpp:277`), and streams the experts of layer L+1 through a 384-slot ring while layer L's attention runs (`src/prefill/prefill.cpp:~280-340`, `DETAILS.md:1384-1386`).
- **`--vram-elastic` / `POST /v1/vram`** (opt-in, one NVIDIA GPU, server): the cache is allocated in 512 MiB segments and the server can shrink it to free VRAM for another program; missing experts run on the CPU (RTX 5070 Q2_0: decode 44 -> 33 tok/s with 4.3 GiB given back, 78 ms) (`docs/VRAM_ELASTIC.md:8-14, 85-93`). It is a sharing feature, not a speed feature.
- The GPU image encoder is on demand and borrows 1.3-1.4 GB (`VRAM_ELASTIC.md:109-145`).

### 2.4 Disjoint expert cache, exchange rotation, EXPERTDEC
- **Disjoint expert cache** (`STRATA_DISJOINT_ADAPT=1`, opt-in, `docs/DISJOINT_EXPERT_CACHE.md:13-17`): only for *two small GPUs* (helper + primary): keeps helper-owned experts out of the primary's promotion candidates (about 1,900-2,000 duplicate slots seen). One contributor's A/B: generation 81.5 -> 94.1 tok/s, 2x RTX 3080 20 GB, IQ3_S, 32K (`DISJOINT_EXPERT_CACHE.md:35-47`). Not relevant to one GPU.
- **Exchange rotation** (`STRATA_EXCHANGE_ROTATE=1`, opt-in): an adaptive swap hands buffer ownership over instead of memcpy-ing the evicted blob into the RAM slot; ~1.4 GiB more page-locked RAM (`docs/EXCHANGE_ROTATION.md:3-9, 62-66`). RTX 5090 + 64 GB, Swift IQ3_S, ~30 swaps/window: 164 -> 188 tok/s, agent turns 155 -> 178 (`DETAILS.md:1492`); RTX PRO 6000 Q2_0 token-identical A/B 104.90 -> 113.44 tok/s (+8.1 %, one pair; `EXCHANGE_ROTATION.md:172-176`); an RTX 3060 run "never reached READY" (`DETAILS.md:1311`).
- **EXPDEC** (`STRATA_EXPDEC=1`, kernel option): gate/up of the *resident* experts with the group's q8_1 rows staged in shared memory; bitwise the default kernels; +1.1 % end to end on a 2080 Ti at 131K; on by default only on gfx12 (`docs/EXPERTDEC.md:209-244, 309-314`).

## 3. SSD reading

### 3.1 Experts (only in the low-RAM modes)
- Experts are *read in place from the GGUF shards* (or `experts.bin`) on Linux; all paths use O_DIRECT or the page cache chosen at start:
  - **Tier choice** (`expert_source.cpp:914-1010`): `file_tier_unbuffered` decides unbuffered vs page cache from MemAvailable/cgroup room, then times both ways once at start - O_DIRECT 1 MiB random preads on **8 threads** against first-touch of mapped pages on **3 threads**, 96 regions x 2 rounds (804-905); unbuffered only if the drive is fast and direct is clearly faster (the rule `file_tier_prefers_direct`); `STRATA_UNBUFFERED_LOAD=1/0`, `STRATA_FILE_TIER_PROBE=0` override. Reason given: PCIe 5 NVMe 8 GB/s direct beat the cached path by 3-4x decode; on 1.7-2.5 GB/s NVMe the cache decoded faster (`expert_source.cpp:~990`).
  - **Unbuffered batch reads on Linux = native AIO** (`io_submit`/`io_getevents`, no library, `expert_source.cpp:69, 2868-2990`): O_DIRECT descriptors, 4 KiB aligned windows merged across gaps <= 32 MiB, up to **256 requests in flight per thread**, a thread-local aio context and aligned buffer. Used by the stager (prompt/fill copies): 4 threads when pages are cached, **32 threads and a 128-deep ring when on SSD** (`DETAILS.md:1065`, `STRATA_STAGER_THREADS`).
  - **Decode, page-cache tier (Linux defaults, `DETAILS.md:285-298`):** zero-copy (`STRATA_COLD_OVERLAP=4`): an expert whose three tensors' pages are all cached (checked with `mincore`) is computed straight from the mapping; io prefetch (`STRATA_IO_PREFETCH=1`): **8 I/O threads** (`STRATA_IO_PF_THREADS`, `generate.cpp:7619-7634`) `pread` whole blobs of the layer's uncached experts and the predicted ones into the page cache (`io_worker`, `expert_source.cpp:1261`); a decode gate re-judges the read-ahead every 16 windows. Everything is switched off when every expert is in the GPU caches (new since 0.2.11, `DETAILS.md:298`, S11 diff `DETAILS.md:295`).
  - **Which experts are prefetched:** `RouterLookahead` (`include/strata/core/expert_source.hpp:313-380`; started `generate.cpp:9015-9060`): when the pool starts layer l, a worker applies **layer l+1's router (BF16 host copy) to layer l's MoE input**, takes each token's top-10 (`STRATA_LOOKAHEAD_K`), drops experts held by the GPU cache/RAM copy and warms the rest; depth 1, 2 when io prefetch is on (`generate.cpp:9045-9094`, max 4). It only warms pages. This is the same "router trick" as ours (our T04/T28 predictors). No accuracy number is published in the docs I read (`STRATA_LOOKAHEAD_STATS=1` can measure it, `DETAILS.md:325`).
  - RAM cache policy for file-read experts = kernel page cache (LRU-like) beside the static profile-ranked RAM copy; nothing of their own beyond the optional RAM_ADAPT swap above.
- **Published numbers for these modes:** (a) 12 GB card emulated on a 72 GB card, Q2_0 GGUF in place, cgroup RAM limit, 3 pairs: with 32 GB RAM decode story/code/doc8k 34.0/28.0/21.7 -> 57.6/71.7/62.6 tok/s; with 16 GB RAM 1.16/1.25/1.25x; prompts 1.54-1.91x (`DETAILS.md:1484`); (b) RTX 3060 IQ3_XXS `experts.bin` 43 GB, 32 GB cgroup: io prefetch + gate decode 1.38/1.21/1.33x (`DETAILS.md:1485`); (c) SATA-emulated 450 MB/s, 20K prompt 334 -> 822 tok/s with the chunk planner (`DETAILS.md:1488`); (d) UD-Q4_K_XL 71.7 GiB experts, RTX A4000 + 62 GB, 39 GiB in RAM, rest from a 2.1 GB/s NVMe: 14-20 tok/s, 4K prompt 134-144 tok/s vs llama.cpp 14.8-16.5 / 117-123 (`docs/QUANTS.md:134-143`); RTX 5070 + 64 GB UD-Q4_K_XL budget 40 GiB: 7-8.5 tok/s (`DETAILS.md:1480, 1597`).
  Strata's own statement: "an NVMe SSD matters, because experts that fit neither VRAM nor the RAM budget are read from it for every token" (`docs/UNSLOTH_Q4.md:~62`). There is **no SSD-bandwidth-aware scheduler of experts beyond the lookahead above, the gate, and the chunk planner**.

### 3.2 The n-gram (PLE) table, 28.8 GB IQ4_NL
- Layout: `per_layer_token_embd` = 320,001,536 rows x 90 B (IQ4_NL, 160 values), i.e. 16 heads x (bigram + trigram hash of the last 3 token ids) (`include/strata/kernels/ngram.hpp:44-56`, `PLE_TABLE_ROWS` 49). Row indices are a host hash of the token ids, so **known as soon as the token (or draft token) is known**. Formats read: IQ4_NL, Q5_0, FP8 E4M3 (+scale), Q5_1, Q8_0, Q4_0, BF16, NVFP4 (`ngram.hpp:62`).
- **Default `--ple-io direct`** (`generate.cpp:665`, `DETAILS.md:1064`): unbuffered (O_DIRECT) 4 KiB reads, never through the page cache (`include/strata/ngram/ple_reader.hpp:1-17`, `ngram.hpp:150-158`: a live mapping of the same file serialises the direct reads, 311 -> 1,575 us/token). `PleReader` (`src/ngram/ple_reader.cpp`): one worker thread owns the `DirectFile`; reads go to a pool of **16 blocking `pread` threads on Linux** (`STRATA_IO_THREADS`, `src/platform/direct_file.cpp:61-64, 264-319`; 4 on Windows with IOCP); `max_inflight` 256 (`--ple-inflight`, `generate.cpp:668`: 64 left the SSD half idle, 32K prompt 303 -> 189 ms).
- **Dedup/sort:** rows of a ticket are folded by 4 KiB page, sorted by offset, merged into 1-2 page jobs; stack path for <= 64 rows (a decode step's 16), hash path for prompt chunks (`ple_reader.cpp:459-545`).
- **Row cache** (`--ple-row-cache`, default 1,048,576 rows = ~95 MB at 90 B): 8-way set-associative, round-robin replacement inside a set (`ple_reader.cpp:28-69`; `generate.cpp:667`). The frozen corpus would serve up to 82 % of reads with 1M rows; within one long prompt 20-34 % of rows recur (`ple_reader.hpp:14-16`).
- **Lookahead:** `PleTable::prefetch_rows` issues the 16 rows **non-blocking as soon as each window token or draft token is known** (`verify.cpp:3291-3300` window tokens; `src/core/mtp.cpp:1763-1770` each MTP draft; `generate.cpp:18950-18975` DFlash2 drafts); `gather_batch` (`ngram.cpp:560-620`) then matches the window's tokens to the in-flight tickets without a second read. The layer-1 consumer waits at `*flag` (`verify.cpp:3512-3522`, comment "NVMe PLE reads overlap with the draft and layer 0's attention + router + experts"). The window only hides the read behind embedding + layer 0.
- **SSD keep-alive:** one random table page every 100 ms when idle for up to 60 s (`STRATA_SSD_KEEPALIVE`, `generate.cpp:5450-5460`, `ple_reader.hpp:75-81`): some SSDs drop into a power state after ~250 ms and stall the next reads 50-150 ms (WD_BLACK SN7100 on Windows).
- **Policy when RAM is spare** (new): `--ple-io ram` (mlock the whole table) is chosen by the engine when RAM >= table + all experts + 8 GiB (`generate.cpp:5474-5509`, `include/strata/core/ple_residency.hpp:25-34`); setup writes `--ple-io ram` on Linux when RAM >= model need + table + 16 GB (`strata_control/setup_config.py:~268-282`). Measured: PLE block of an 8K prompt 845 ms direct / 451 ms mmap / 132 ms resident (R9700, IQ3_S; prompt 2,125 / 2,368 / 2,611 tok/s; `generate.cpp:5480-5490`); RTX PRO 5000: 4K prompt 1,298 -> 1,059 ms with RAM, 20K -9 %, 98K -2 %, decode +0.8 % (`setup_config.py:~270-277`); `--ple-io ram` locked decode "up to 6 % faster" (#4671, `ngram.cpp:~487`). Startup probe warns below 15K rows/s (`DETAILS.md:1064`, `generate.cpp:5521-5555`).
- **Quality of the table format** (measured vs the checkpoint's own BF16 table, 4,000 random rows): per-row error Q8_0 0.53 %, FP8 2.64 %, Q5_1 3.78 %, Q5_0 4.25 %, IQ4_NL 7.60 %, Q4_0 8.55 %; mean KL vs BF16 table IQ4_NL 0.0146, Q8_0 0.0125 (`DETAILS.md:1577-1580`). The default ISTA table is IQ4_NL, i.e. already a quantisation of the original table.
- Cost per token: 16 rows on up to 16 pages = at most 64 KiB read, <= 23 KB "read per token" in the paper (`docs/paper/Strata-Paper.pdf` Table 1; text extracted from the PDF, unchanged between S11 and S).

### 4.4 Answer to "gate/up Q3_K + down Q4_0 / Q2_0"
- **Down Q4_0 and Q2_0 are supported** (D list has 2 and 42). **Gate/up Q3_K is not**: `native_expert_supported` (`iq_kernels.cu:5480-5485`) requires `gu_qk(type) > 0`, and `gu_qk` comes from `STRATA_GU_FMTS`, which has no 11. `generate.cpp:4660-4676` runs this check for **every layer before anything is allocated** and exits: *"layer N's experts are Q3_K/... (ggml types 11/..), which this engine has no GPU kernels for"* (return 1). The docs say the same in general: "the engine checks every layer's formats at start and refuses an unsupported one by name" (`docs/UNSLOTH_Q4.md:271-272`).
- Q3_K *is* supported for dense matvec (`native_mmvq_supported` accepts 11, `src/kernels/cuda/native_mmvq.cu:3520-3524`) and the token embedding (`dq_q3_k`, `iq_kernels.cu:3325`).
- A second, structural reason against K-quant downs: down rows have n_ff = 640 values and K-quants need 256-value super-blocks (640 = 2.5 x 256); `native_fmt` rejects it ("expert geometry is not whole blocks", `native_expert.cpp:278-283`), and the CUDA source says "Flash-Next's FF 640 never selects them" (`iq_kernels.cu:853`). Gate/up rows have 2560 values (10 x 256) so Q3_K gate/up would fit geometrically; only the kernel is missing (inferred: adding a `Fmt<11>` plus a CPU path would be needed; I did not test).
- Not covered: whether a mixed pair "Q3_K gate/up, Q4_0 down" has ever been tried by Strata (nothing in docs/tests: grep of `docs`, `tools`, `src` finds Q3_K only as dense/embedding, as `UD-Q3_K_XL` (a set name, whose experts are IQ-types), and in MMVQ_IL tables).

## 6. Everything that changes the model's answers

Legend: ON/OFF = default in S; S11 = same unless a note says otherwise. "Pub." = published speed effect.

### 6.1 ON by default
1. **Route tail skip - `STRATA_ROUTE_TAIL_SKIP=7`** (ON by default on CUDA; S11 same: S11 `generate.cpp:12600`).
   - What: in a decode/verify window, a *missed* expert (not in the VRAM cache) that **every token of the window routes at router rank >= 7 (0-based: ranks 7, 8, 9, the three smallest weights)** is neither copied nor computed; its row is zero and the other experts keep their router weights (no renormalisation) (`src/core/expert_source.cpp:4869-4883, 4961-4983, 5034-5036, 5259-5262`; comment "changes the output", `generate.cpp:12821-12826`). Resident experts at rank >= 7 are still computed.
   - Off automatically: all experts resident; >= 90 % of experts cached (`STRATA_TAIL_SKIP_MAX_CACHED`, 60 % on an AMD layer split); `--batch`; peer/helper GPU; NVFP4 experts ("moved answers by about as much as its quantization does", `generate.cpp:12835-12862`); HIP except gfx12 (`generate.cpp:2504-2515`).
   - Introduced 0.1.42 (register first_date 2026-10-09, `data/settings-register.json:34293`; the 2026-10-01 study predates it). Setup writes `STRATA_ROUTE_TAIL_SKIP=0` for Unsloth files where every expert is in RAM, except Linux AMD gfx12 (`docs/UNSLOTH_Q4.md:~46-52`).
   - Pub. quality: teacher-forced KL vs 0.1.41 behaviour 0.0058 / 0.0056 (RTX 3060 IQ3_XXS greedy / sampled), 0.0032 / 0.0030 (A4000 Q2_0); top-1 agreement 97.7 / 97.5 % and 98.2 / 98.2 %; perplexity x1.011 / x1.005; same-engine floor 0.0006-0.0007; HumanEval (82) 76 / 78 vs 78, 76 / 76 vs 76 (`DETAILS.md:1520`). For Unsloth files it costs more: UD-Q4_K_XL yardstick KL vs Q8_0 0.056 -> 0.086 (R9700, every expert in RAM) and 0.053 -> 0.115 (A4000, RAM-budget mode) (`QUANTS.md:158-162`).
   - Pub. speed (5 interleaved pairs, default over `=0`): RTX 3060 IQ3_XXS story/code/6K doc x1.104 / x1.197 / x1.241 (5/5); RTX A4000 Q2_0 x1.151 / x1.135 / x1.101 (5/5); Tesla P100 IQ3_XXS (`--pcie-frac 0.29`) x1.149 / x1.182 / x1.118; 2x A4000 layer split (99.7 % hit rate) x0.998; V100 32 GB Coder 94.8 % cached: -1..2 % decode and draft acceptance 70.1 -> 68.2 % (`DETAILS.md:1521`). Unsloth: +4-10 % (all in RAM) and +26-67 % (RAM budget) decode (`QUANTS.md:160-162`). Engine banner: "+10..20 % decode on 12-16 GB cards that miss experts" (`generate.cpp:12866`).
2. **Prompt CPU share - `STRATA_PREFILL_CPU_SHARE` (auto), limit 3,072 tokens** (S = S11: `include/strata/prefill/share_rules.hpp:21-29` identical): for prompt chunks below the limit the idle decode CPU pool computes non-resident experts that few tokens route to while the GPU does the rest; share per layer measured so both sides end together (`src/prefill/prefill.cpp:278-335`). Not for layer split, batch slots, HIP except one gfx12 card (limit 1,536 there with fused kernels). Output changes in the last bits: mean KL ~0.004 below 1,024 tokens, ~0.011 at 1-3K (`prefill.cpp:287-290, 2987`; `share_rules.hpp:16-20`). Introduced 0.1.41/0.1.42 (limit raised 1,024 -> 3,072 by "owner decision 10-31"). Pub. speed: 512 tokens -28..-34 % prompt time, 1,000 tokens -20..-26 % (8/8 pairs; RTX 5070 Q2_0 1,376 -> 1,019 ms at 512 tokens, RTX 3060 IQ3_XXS 1,620 -> 1,159, P100 4,805 -> 3,126) (`DETAILS.md:1518`); up to 3K: RTX 5070 Ti PCIe 3.0 x8, Swift IQ3_XXS 512 / 1,000 / 2,000 / 3,000 tokens -49 / -41 / -38 / -22 % (`DETAILS.md:1519`); RTX PRO 5000 1K +151 %, 2K +45 % prompt speed (`share_rules.hpp:18-20`). Not applied to decode.
3. **PCIe share / CPU-vs-GPU split of misses** (`--pcie-frac`, auto-refined `L/(L+kR)`, `DETAILS.md:1055`): the GPU computes a fraction of the missed experts from pinned RAM instead of the CPU. Not an approximation of the model, but "the CPU lane rounds a missing expert's FP32 rows differently from the GPU lane", first-token KL 0.0013 (gfx12, `generate.cpp:2527-2534`), 0.0015 (RTX 3060, `DETAILS.md:1522`). Setting it to 0 gives byte-identical text (`DETAILS.md:351`). Pub. speed (with tail skip on): RTX 3060 IQ3_XXS share 0.55 -> 0.20: x1.300 (5/5).
4. **Expert cache vs no cache** (GPU rounding differs from CPU): 95-98 % same top-1, median KL 3e-4..4.5e-3, perplexity delta -0.005 +- 0.005 nats; "explicitly not claimed" to be identical (`generate.cpp:8465-8471`, `bench/results/2026-09-27-cache-parity`; earlier study). Adaptive tier makes text non-reproducible (`DETAILS.md:573`).
5. **K/V precision:** setup writes `--kv int8` above 8K context (`setup_config.py:221`); int8 is lossy vs fp16. `--kv q4_0` (Hadamard-rotated 4-bit, opt-in): about 4 % faster at 128K, perplexity +8-12 % (`DETAILS.md:234`); `--kv k8v4` (INT8 K + rotated Q4_0 V, -23 % KV memory): prompts 2-5 % slower, decode 99 vs 85 tok/s on RTX 3090 Coder 198K (`DETAILS.md:235, 1437`). No numbers published for int8 vs fp16 quality (not found).
6. **Prompt-path rounding defaults:** cc 12.0 cards with >= 80 SMs: fused int8 prompt experts (`STRATA_PF_FUSED`, KL vs MMQ 0.0002 RTX PRO 5000; `DETAILS.md:1057, 1524`); `STRATA_PROMPT_ATTN_IMMA` int8 prompt attention (`DETAILS.md:1120`); `STRATA_GDN_TC`/`CONVL2` on Linux CUDA (S-only default; KL mean 0.0019, max 0.0125; prompt +4.4 % at 4K, +5.5 % 16K, +5.7 % 32K; `include/strata/core/arch_defaults.hpp` new text); prompt chunk 32,768 (first-token KL ~1e-4); `STRATA_GR_V3`. Lower-level and prompt-only.
7. **Pack conversions in the file:** small tensors (195 Q8_0 hyper-connection / PLE value projections) rounded to BF16 (max abs err 0.0144) unless `STRATA_HC_Q8` reads the Q8_0 (`docs/UNSLOTH_Q4.md:~119-128`); on A4000 UD-Q4_K_XL this alone moved KL vs Q8_0 0.0562 -> 0.0526 (`QUANTS.md:164-167`). The default PLE table is IQ4_NL (section 3.2).
8. **Speculative decoding** is acceptance-by-argmax-match for greedy; at temperature > 0 the default is "sample from the target, accept if equal" (distribution-preserving as the draft is deterministic); `STRATA_SPEC_COUPLED`, `_GUMBEL`, `_PROB` (rejection sampling) are opt-in (`DETAILS.md:574-609`). Draft vocab subset (default includes CJK, 40,525 tokens in the old study) changes only drafts. Exact except for the CPU rounding noted in section 1.

## 8. What changed since our 2026-10-01 study (HEAD d6708a4 -> 13eedf5)

Old study facts that still hold: static profile fill, global ranking, adaptive swap every 4 windows / 96 / decay 0.7, slot-0 read-back, one graph + spin-wait doorbells with no host driver sync, cache on/off parity "not claimed", PLE rows prefetched per draft token (`docs/others-code-study.md:85-142`). Changes:
1. **Scope:** one model on one machine class -> Qwen3.8-FN in many packs (Q2_0, IQ2_XS, IQ3_XXS, IQ3_S, Coder, Swift 1.5, Gyro, Unsloth UD-* 3-8 bit incl. v3.1 sets, NVFP4, Orca), Qwen3.6-35B, DeepSeek V4.1-Flash engine (SSD streaming of a 240-270 GB model; `README.md:55-87`), backends CUDA/HIP/SYCL/Metal, layer split, batch slots, app + Terminal + server (`AGENTS.md:15-37`).
2. **RAM-short operation exists now:** `--mmap-experts`, `--resident-experts`, `--resident-budget-gib`, automatic RAM-copy fallback, Linux file tier (zero-copy, io prefetch with `RouterLookahead`, decode gate, AIO/O_DIRECT, drive probe, prompt chunk planner), `STRATA_RAM_ADAPT` (section 2.2/3.1). The old study said "everything assuming all experts in RAM does not apply to a 69.8 GB model on 30 GB RAM"; Strata now has a story for that (still: hottest-experts-in-RAM + page cache, no read scheduler of their own).
3. **Default answer-changing speed-ups added:** route tail skip (rank >= 7, 0.1.42), prompt CPU share (<= 3,072 tokens), PCIe share auto-refinement, GDN TC (engine default since after 0.2.11), per-arch bitwise sets, fused int8 prompt experts; ROUTE_PRIOR added in 0.2.7 and withdrawn in 0.2.8.
4. **Drafting:** MTP (up to 3 drafts, `--spec 4`) + prompt-lookup/suffix windows up to 12 tokens + **DFlash2 block drafter as Auto on CUDA** (Apache-2.0, 1.2 GB; window 6, conf 0.35-0.8 by slot count; measured gain over MTP ranges from -6.5 % to +9.3 % depending on slot count and confidence, e.g. 1,383 slots: -4.2 / +3.1 / +7.1 / +9.3 / +8.7 % at conf 0.35 / 0.5 / 0.65 / 0.8 / 0.9, `strata_control/drafting.py:257-275`).

## 10. Short list of things worth taking back (my reading, "inferred")
1. Router-trick lookahead is *already* their prefetcher for file-read experts (next layer's router on this layer's input, top-10, drop resident, warm pages; depth 2) - same idea as our predictor; they publish no accuracy numbers, only end-to-end tok/s.
2. Tail skip (ranks 7-9 dropped if non-resident for all tokens of the window) is the single biggest answer-changing default behind their 12-16 GB numbers after 0.1.42 (+10-24 % decode on 12-16 GB cards; KL 0.003-0.006). Our "no expert skipping" rule means their post-0.1.42 numbers are not comparable; the 0.1.26 tables and the llama.cpp head-to-head (0.1.40) are.
3. Their low-RAM tier is a static profile-ranked RAM copy + kernel page cache + optional swap, i.e. nothing like our SSD scheduler; the published 32 GB / 12 GB numbers (57.6-71.7 tok/s on an emulated card at 32 GB) come from zero-copy compute out of the page cache and io prefetch.
4. Q3_K gate/up experts are refused at start; down Q4_0/Q2_0 and gate/up Q4_0/Q2_0/IQ-types work. Q2_0 (type 42, 64 values / 18 B) is first-class on CPU (AVX-512/AVX2/AVX1) and GPU.
5. Open points I could not settle from the repo alone: the real accuracy of the lookahead predictor; int8-vs-fp16 KV quality; whether any published tok/s exists with tail skip, CPU share and PCIe share all off; behaviour on Zen 5 (HX 370) specifically (code path would be the AVX-512 VNNI/VBMI one, inferred from `expert_layout.hpp:~27-45`).
