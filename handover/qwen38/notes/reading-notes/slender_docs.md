## 0. Things found while reading that matter for how much to trust the numbers

1. **WORKLOG has no section for most of the 2026-11-06 to 11-07 prompt/memory work.** `K/V lend`, `STAGER`, `DENSE_ARENA`, `AUTO_MAX`, `PREFILL_RING` have 0 hits in `WL` (grep count). Their numbers (K/V lending +11%, in-place stager +8.5/+9.2/+13.9%, DIRECT_BATCH +9%, 6-pass 1,741 -> 1,879) exist only as one-line table rows in `PERF:48-71` and `FORK.md:66-67`. No run counts, no raw data, no "before" settings are in the repo for them. `memtools/` (the scripts and run folders the WL cites) and `pf_probe.py` are not in the tree (`ls slender | grep memtools` empty; `tools/` has no pf_probe).
2. **`FORK.md:6` says "With the MTP drafter, the 0.2.11 build measured the same as the 0.1.55 one (3 runs each, worklog)"; `WL` has no such entry** (grep for `0.2.11` in WL: no hits; `0.1.55` only at WL:5 and WL:714).
3. **Skip 7 is in every number up to and including the 2026-11-05 batches; skip 0 only from 2026-11-06.** WL:1278 says it outright: "The daily setup already skips experts. `STRATA_ROUTE_TAIL_SKIP=7` is on by default on both engines ... Every speed in this log and the 'no skipping' estimate above include it, except the identical-output checks." `PERF:60` says the 2026-11-06 section onward is "Skip 0".
4. **"Skip 0" does not mean "every rounding-changing part is off".** `generate.cpp:3359-3361` sets `STRATA_PREFILL_CPU_SHARE_MAX=1024`, which still leaves Strata's CPU share of experts ON for prompt chunks below 1,024 tokens (see section 3, item B2). `FORK.md:157` says so: "STRATA_PREFILL_CPU_SHARE splits short prompts by measured timing, and upstream's reproducibility list does not turn it off." The K/V cache is int8 (`--kv int8`) and the model is an IQ3_S quant in every run.
5. **Two different "rings" are named in the docs.** `STRATA_STAGER_RING=128` (fork default, `generate.cpp:3375`) = the number of pinned host buffers the stager threads fill (`prefill.cpp:698`, `kRing = 16` upstream). `STRATA_PREFILL_RING=192` (not a default, "this PC's launcher", `PERF:37`) = the GPU-side staging ring of the prompt path (`prefill.cpp:404-440`). The fork default for the GPU ring on this PC is 96 slots (`PERF:24`, `ROOM:13`), taken from `ring_slots()`'s "96 when a large share goes through host copies" branch (`prefill.cpp:315, 436-437`).
6. **The "after 50K" / "after 26K" numbers are decode speed after a long prompt, the "prompt read" numbers are prompt tok/s, and the prompt sizes differ between tables**: 26,272-token prompt in the 11-03..11-05 tables (WL:192), 50K in the 11-07..11-09 tables (PERF:17-18, 48).
7. A contradiction between fork docs and upstream's docs: fork recommends `--pcie-frac 0` (PERF:66: "7% less time a step; 29.1 -> 33.9 tok/s after a 50K prompt (one batch)"); `docs/DETAILS.md:349-350` says "`--pcie-frac 0` costs decode speed, so keep it for A/B runs".
8. `FORK.md:195` says `STRATA_POOL_FUSED` gave "about 0.5% over a whole run"; `WL:1197` says "about 0.6 ms of a 45 ms window (about 1.4%) ... doesn't show in tok/s". Different phrasing of the same test; the WL number is the more detailed one.
9. The `FORK.md:89-90` "Settings used for the result" block lists `STRATA_ROUTE_TAIL_SKIP=0`, but the Result table it belongs to was measured with skip 7 on both engines (`FORK.md:50`). The block is the current recommended setup, not a replay of the table's runs (inferred).

### 1.2 Method (all tables)
Fresh engine per run, mixed/interleaved order, "text" = mean of coding prompts (4 or 6 answers, 450 tokens in the 11-05 batches), model-card sampling (temperature 1.0, top_p 0.95, top_k 20, thinking on) from 11-05 on, temperature 0.6 before that (FORK.md:209, WL:184, WL:448). 3 runs a setting in the headline tables (5 in the 11-03 table). Raw run files / scripts are not in the repo (see 0.1).

### 4.2 What a prompt does (the model, per `ROOM:29-40` and the code)
- 24,576 experts (48 layers x 512), ~47 GiB, ~2 MB each; ~4 GiB in the VRAM cache (1,978 slots, 3.80 GiB, `WL:635, 701`), 10 GiB in the RAM tier (5,272 experts), the rest on the SSDs.
- A prompt is read in chunks; per chunk every expert not already in VRAM is streamed (RAM tier by DMA, SSD file tier through the stager) and used for all the chunk's tokens. The number of chunks = number of passes over the experts, "each pass takes about 4 seconds here, most of it reading" (ROOM:33-34). 50K in chunks of 8,448 = 6 passes; in chunks of 10,240 = 5 (ROOM:36).
- The chunk size is limited by VRAM (activations, attention scratch, the staging ring). Buffers live in a "loan": while a prompt is read, the expert cache lends its last slots; they are refilled after the prompt. "The loan's size is fixed when the engine starts, and it decides the largest chunk" (ROOM:38-40).
- Chunks < 1,024 tokens: "staged after their routing" with the CPU share (`prefill.cpp:293-296`); chunks >= 1,024 (`kStreamAllMinDefault`, `prefill.cpp:239-245`) stream every non-resident expert in a fixed order through a ring (`ring_slots()`, `prefill.cpp:404-440`).

### 4.3 The stager, in-place reads, staging ring (code)
- `struct Stager` (`prefill.cpp:690-` ): "the experts the arena could not pin (a third of the streamed ones on IQ3_S) are copied into pinned buffers by these threads, ahead of the launches. Copied in line by the launching thread they left the GPU without queued work while each ~2 MB memcpy ran (~15 s of a 32K prompt on IQ3_S)" (`prefill.cpp:690-697` comment). Job j lands in host buffer `j % kRing`.
- With `STRATA_STAGER_IN_PLACE=1` the stager calls `FileExpertSource::copy_blob_aligned` (`expert_source.cpp:4072`): a 4 KiB-aligned pinned buffer; the blob read unbuffered (`read_direct`) straight into it at `buf + skip` (sector offset), buffer 8 KiB larger. Falls back to the normal copy when the blob is in the RAM copy, the GGUF is read in place, or no unbuffered handle exists.
- Fork defaults for the stager on a pack: `STRATA_STAGER_THREADS=3`, `STAGER_BATCH=1`, `STAGER_RING=128`, and `g_fork_pack_defaults` makes the in-code default 3 threads instead of 4 (`prefill.cpp:1874`): "with the in-place reads the drives stay in their fast mode". Windows stager threads spin; Linux sleeps (`prefill.cpp:238-250`, `STRATA_STAGER_SLEEP`).
- GPU ring: 96 slots on this PC by default (`pinned_share < 0.9` -> 96, `prefill.cpp:436`); `STRATA_PREFILL_RING=192` + lend 95% only in the author's launcher: "The deeper ring helps only where the prompt's chunk stays the same size with it ... on other cards it hasn't been measured, so it isn't a default" (PERF:41-42).

### 4.4 The prompt room (ROOM, whole page; code `generate.cpp`, `native_head.cpp`, `dflash2.cpp`, `prefill.cpp`)
- Idea: three VRAM blocks sit unused while a prompt is read: drafter weights (DFlash2 pack 323 MiB / MTP experts 675 MiB), the DFlash2 draft head (81 MiB), the output head `output.weight` (497 MiB) (ROOM:46-50). The chunk's buffers continue from the loan into these blocks (~900 MiB more, enough for a 10,240-token chunk at the default 32K K/V window, ROOM:52-53). Nothing is freed or moved; contents are written back in place: DFlash2 pack + draft head from a pageable RAM copy made at the first long prompt (~400 MiB), MTP experts from a pinned copy (675 MiB), the output head re-read from the model file straight into the same address (~130-150 ms, `NativeHead::room_reclaim`, `native_head.cpp:~300-330`; Windows uses `upload_direct` unbuffered reads, `native_head.cpp:76-118`). Same addresses keep the decode's captured CUDA graphs valid (ROOM:63).
- Start-up: biggest chunk (steps of 256, margin 64 MiB per region) is computed and printed: `a roomed prompt reads in chunks of up to 10240 tokens` (`generate.cpp:11205-11245`; margin `(pr_head_on ? 3 : 1) * 64 MiB`). Host buffers sized for that chunk once (`Prefill::set_max_chunk`, `prefill.cpp:1810-1830`, header `prefill.hpp:94`).
- Per request with >= 4,096 NEW tokens (`STRATA_*_ROOM_MIN`): waits until drafter and head are idle, makes the RAM copy, marks blocks lent (`Dflash2Drafter::room_lend` `dflash2.cpp` diff; `NativeHead::room_lend`); while lent, `draft()` / `context()` / `NativeHead::run()` refuse (errors, not wrong text; `dflash2.cpp:1096, 1147`, `native_head.cpp:~340`); drafter's per-token inputs (tap rows) are held in RAM; `Prefill::relayout` lays out buffers loan-first then borrowed blocks (up to 4, `kRooms`, `prefill.cpp:2171-2210`); the room closes before the first verify window or at prompt end (`generate.cpp:17214, 17271, 18532-18533`). A room left open by a cancelled request is closed at the next one (`16261, 16325`).
- How found (ROOM:92-112): trace timeline (`STRATA_TRACE=1`) shows much of a 50K prompt waits for streamed experts and GEMM-input conversion; both scale with passes; ordinary knobs (`--kv-resident 16384/8192`, lend 100%) gave chunks up to 9,728 (6 passes); `--prefill 10240` forced -> 1,335 tok/s; the RX 6600 branch's drafter parking (`STRATA_DF2_PARK`) rejected; room-as-ring-slots no gain; room-for-buffers 5 passes but shallower ring no gain; heads added -> +11%; a bug (first verify window ran before the room closed and read prompt buffers instead of the head; engine's non-finite-score check caught and retried it, no wrong text) fixed in `3349aaca`.
- Checks (ROOM:114-125): `DF2_ROOM_VERIFY` checksum matched every run; first-token KL (temperature 0, full vocabulary) vs same build without room: 0 at 3K (no room), 0.0022 at 29K, 0.0003 at 50K, same top token; two no-room runs 0 against each other and two room runs identical -> "the difference is the chunk size's rounding, not noise"; 64-token answers identical at 3K, reworded after ~40 tokens at 29K / 50K.
- Limits (ROOM:127-134): one GPU, `--serve` only; not with layer split, `--prefill-head-alias`, or (MTP) `--batch`; needs the native output head in VRAM read from file (else HEAD steps aside); costs ~400 MiB pageable (DFlash2) or 675 MiB pinned (MTP) of RAM; on other cards the gain depends on how close the prompt was to one pass fewer.

### 4.5 Fused hyper-connection read (ROOM:136-141; `prefill.cpp:568-580, 4146-4164`)
`STRATA_HC_UPMIX=1`: the prompt path's hyper-connection up GEMM and `gr_mix_r` as one kernel (upstream's kernel `gr_upmix`, upstream opt-in on CUDA: `strata-0.2.11/src/prefill/prefill.cpp:530-545`); only chunks >= 33 tokens, sm_80+; older cards keep the pair; "Decode doesn't use it". 50K +4.3%; logits byte-identical; `STRATA_HC_UPMIX_CHECK=200` 96 of 96 reads exact.

### 4.6 Refill after a prompt
Lent GPU cache slots are refilled from the RAM tier / file after a prompt. After a 50K prompt refill took 1,048-1,059 ms with the default; `STRATA_REFILL_PINNED=4` (N threads, runs of 2 blobs each, own pinned buffers and streams, `generate.cpp:527-560`) -> 405-414 ms; after short prompts 190 -> 70 ms (PERF:36). The "narrow head-alias loan" experiment reports refill bytes -67% (WL:1108). Gen. refill at the end of a prompt is also why short turns pay ~0.4 s (WL:1174).

### 4.7 Dense arena (`STRATA_DENSE_ARENA`, `native_dense.cpp:176-181`)
One VRAM allocation for the dense matrices so the 2 MiB granule rounding (`kAllocGranule`, `native_dense.cpp:36-38`) is paid once; freed VRAM goes to the cache/loan; part of the "50K in 6 passes" row (PERF:48); no isolated measurement.

### 4.8 GDN state, n-gram (PLE) rows in prompts
The five fork documents do not discuss GDN state or PLE rows in prompts. What is stated elsewhere (inherited docs): the 28.8 GB n-gram table is on the SSD, "a few rows per token, read unbuffered past the OS cache (`--ple-io direct`)" (`docs/DETAILS.md:1358-1359`, `1059`); `STRATA_GDN_CHUNKED` is an opt-in prompt DeltaNet recurrence in 32-token chunks (rounding; `DETAILS.md:1077`); the 2026-11-04 memory map found "33 blocks of about 21 MiB, on the first long prompt ... Not identified" (WL:549-551); the fork's `layer.cpp` diff only adds `st.host_h`/`st.host_d` pointers for K/V lending (`layer.cpp:931-936`).

### 4.9 PCIe and RAM use during a prompt
- PCIe: measured 24.1 GB/s probe on PC-A (WL:837, 690); ~0.218 ms per 2 MB expert at 14.2 GB/s in the (older) analysis; RTX 4060 laptop link narrower. Prompt experts on the RAM tier cross by DMA; unpinned ones (about a third on IQ3_S per `prefill.cpp:690`) via the stager.
- RAM tier is NOT modified by read-through during prompts: `through_context()` returns if `n_tok > 16` ("decode windows only: a prompt's chunks would churn the tier", `expert_source.cpp:2433-2435`).
- RAM: PC-A lowest free RAM during the 11-08/09 runs 3.5-4.4 GB, page file 0 GB/h (PERF:20-21); the prompt room keeps ~400 MiB (DFlash2) / 675 MiB pinned (MTP) of RAM after the first long prompt (PERF:119-120). Layer-major needs pinned RAM for residual rows and steps down by halving when not available (`prefill.cpp` diff near 6576-6600, message `no pinned RAM for a ... -token super-chunk`).

## 5. Expert cache, SSD reading, RAM cache

**Tiers on PC-A** (FORK.md:109-114, PERF:104-118, WL:635, 701, 914): (1) VRAM expert cache: the engine "sizes its expert cache to fill the card and keeps about 0.7 GB free" (PERF:104-105); 1,978 slots = 3.80 GiB with `--kv-resident 32768` (WL:701; "All K/V in VRAM" leaves only 367 slots = 0.71 GiB), 2,102 slots with DFlash2 loaded (WL:727). Adaptive: `--adapt-every 4 --adapt-swaps 24` (`tools/fast_setup.py:379`), swap rounds take ~3 windows regardless of size (WL:374); 76% of swaps paid off (WL:374). Hit shares ~55-60% VRAM / ~25-30% RAM / ~7-11% SSD per token (WL:610, 703). (2) RAM tier: `--resident-budget-gib 10` -> 5,272 experts (WL:914); "Experts cached in RAM 10 GiB" (FORK.md:109); the tier is page-locked ("page-locked and mapped" at 10 GiB; at 14 GiB the driver refused and it took 12 s, WL:505, 80); lowest free RAM 3.5-4.4 GB at 10 GiB vs 0.08-0.94 GiB at 14 GiB with 0.8-36.2 GB/h paged (PERF:107-113). (3) SSD: `experts.bin`, the rest.

**SSD API.** Windows: `CreateFileW(... FILE_FLAG_NO_BUFFERING | FILE_FLAG_OVERLAPPED)` per file (`expert_source.cpp:2814, 2832`), `ReadFile` with `OVERLAPPED` (`3236-3250`), every request of a batch in flight before the first wait ("the drive sees the whole batch as one queue"), neighbouring windows < 1 MiB apart merged into requests up to 32 MiB because "NTFS runs the unbuffered reads of a file one at a time while the file is mapped or cached anywhere" (`3119-3128`: measured 10.4 GB/s on an unmapped file vs 3.4 GB/s on a mapped one at 512 KiB, queue depth 48). Linux: `open(... O_DIRECT)` (`871, 2850`) and the kernel's asynchronous reads with `io_submit` (`#include <linux/aio_abi.h>` line 67; comment `3358-3366`, depth 256 per thread, `3459-3463`), falling back to a mapped copy if AIO is unavailable. **No io_uring / IoRing code** (grep: none; IoRing only modelled, +3.3..+5.1%, WL:882, 1385). Two SSDs: Windows only (`STRATA_EXPERTS_MIRROR`, inside `#if defined(_WIN32)`; header comment `expert_source.hpp:1154`); each read >= 256 KiB (`kSplitMin = 256 << 10`) split by `mirror_share` (0.5 default), each half to a different handle; the copy is the same file, sizes only compared (`2828-2837`).

**Measured read costs** (`read_probe`, WL:878-883): 2.2 MiB blobs, half from each drive: 1 blob 415 us, 2: 590, 3: 765, 8: 1,620, 16: 3,000; each extra blob ~180 us (~12 GB/s); serial `ReadFile` submit ~90 us per blob on an E-core, 30 on a P-core but overlapped; "IoRing with registered buffers: about -60 us a batch on the E-core"; sleeping vs spinning +20 us. Per-read 0.18-0.26 ms per expert (WL:635); SSD at 4.4 GB/s in decode, 8.3 GB/s in a rewrite (WL:612); `3,729 GB` read in a 20-minute normal session, ~3 GB/s (WL:239). A fragmented mirror copy (68,990 pieces) read some experts 3x slower (2 GB/s vs 7 with 3 threads) (FORK.md:147).

**Policies.** Experts' usage counts decay each round (decay 0.7; `--adapt-decay`); VRAM swaps = the adaptive tier (upstream); RAM tier: upstream `STRATA_RAM_ADAPT` moves (copy) vs fork **read-through** (a missed expert's read lands in the RAM place of the layer's least-used expert not routed this layer, count < 2 x decay, `expert_source.cpp:2443-2470`); K/V-tail lending (below). Cache-miss audit: "the swap budget limits the cache more than the scoring does ... even perfect knowledge reaches only 63.7% at the current budget"; scoring changes flat; most misses are experts used within the last 4 windows (WL:349-368). Oracle bounds: perfect foresight 78.6% VRAM share, 183 CPU entries/window (WL:360). `Cost-aware ranking adds nothing here` (WL:877). Read-through modelled +10.3..+11.0%, measured +5.2..+13.3% (WL:891-897, 921, 92).

**Lending idle K/V memory to experts.** Yes: `STRATA_KV_LEND` (on by default with a pack). The pinned HOST copy of the streamed K/V is sized for the whole context (13.7 KB RAM per context token, `DETAILS.md:236`); cells a request cannot reach are lent to the RAM tier as read-through places and taken back at the next request's start (`generate.cpp:12944-12952`, `expert_source.cpp:4914`). Measured: SSD misses -27%, short +11% (37.9 -> 42.2). On VRAM side: the prompt loan (cache tail slots) and the room (drafter/head blocks) as above. `--kv-grow` is a different (upstream) VRAM feature.

**Other.** "Lowest free RAM", "Task Manager's rows don't add up" (pinned K/V ~3.0-3.7 GiB outside the working set, WL:55, 530-537); engine working set peak 14.4-14.6 GiB at 10 GiB (WL:553); no leak at exit (WL:539). Page file: 0 GB/h at 10 GiB, up to 138.8 GB/h with an 8 GB app but that script held ~2x memory (WL:233, 507). ## 7. Drafting (MTP / DFlash2 / prompt lookup)

- **What the engine drafts with**: (a) Qwen3.8's own **MTP layer** (`--mtp`, `--spec 4 --spec-min-p 0.5` is setup's default, `DETAILS.md:337-338`; ~0.7-1 GiB VRAM; "every token is still verified"); (b) **suffix + prompt-lookup drafting** (on by default, "when the reply repeats the context ... prompt lookup drafts up to 5 tokens", `DETAILS.md:1362`; `--lookup-chain`, `--lookup-max-t` default 12 on serve CUDA one-GPU 8-row builds, `DETAILS.md:1088`); (c) **DFlash2 drafter** (`--draft dflash2 --draft-model <pack> --draft-fallback none --mtp-draft-vocab <file> --spec 6 --draft-conf C`, no `--mtp`; C from `CONF_STEPS = ((12000, 0.35), (7500, 0.5), (3000, 0.7), (0, 0.8))` by engine cache slots, so ~0.8 here with ~1,978-2,102 slots; `strata_control/drafting.py:217-231, 487`, identical to upstream's file). FORK.md:111: server uses DFlash2 when `Strata-data\dflash2` has its pack, else the MTP.
- **Defaults of the fork**: MTP `--spec 4 --spec-min-p 0.5` (FAST-SETUP), DFlash2 used automatically if the pack is present (`tools/fast_setup.py:395-398`). "Chosen: `--spec 4`. `--spec 5` is within noise on text and lower on image answers" (WL:471).
- **Numbers** (all PC-A unless noted): acceptance row 1-3 of an MTP draft 79-83%, 70%, 61%; each extra draft row costs 11-12 ms (WL:388); tokens per step 1.6-2.4 (thinking on) up to 3.1-3.7 (thinking off) (WL:732-733); `--spec 4` 2.00-2.19 tok/step at 35-38 ms/step (WL:462-464). Each drafter's own time (WL:766-780, Studio config, temp 0, suffix off): DFlash2 draft 2.54-2.57 ms, window 81.5-86.0 ms, acceptance 88.7-92.8% (short), 83.6-87.8% (26K), 1.61-1.71 tok/window; MTP 2.15-2.56 ms, window 104.4-120.2 ms, acceptance 73.5-74.9% / 68.5-73.7%, 2.01-2.05 tok/window; "drafting is about 2-3% of a window". Thinking-on coding: no change (47.4 / 47.4). Fork 11-06 row: DFlash2 follow-ups +5%, 50K prompt reading +11% (PERF:70). Release notes "report about 0 gain in long agent sessions on another machine" (WL:741).
